# RUNBOOK — WayangOS as a wayangi Edge router

Operational procedure: turn a WayangOS box (MiniPC) into an **Edge router** for a
wayangi *site* — public IPv4 `/32` + IPv6 `/64` to the LAN, two WireGuard tunnels
to the hubs, WAN load-balance/failover for a private segment, and the firewall.
Design: [docs/EDGEROUTER.md](EDGEROUTER.md); parity with the MikroTik `.rsc`:
wayangi `docs/EDGE-PARITY.md`.

> **Prerequisite — kernel.** The tunnels need WireGuard (+ VRF / IPv6 multiple
> tables for the tunnel routing) in the kernel. Those options are **off in the
> shipped image** because the accumulated router kernel block freezes the test
> device (an interaction — see [docs/INCIDENT-1.0.13.md](INCIDENT-1.0.13.md) and
> [docs/ROUTER-KERNEL-BISECT.md](ROUTER-KERNEL-BISECT.md)). Until that is fixed,
> this runbook runs against the **QEMU lab kernel**
> (`scripts/build-lab-kernel.sh`) or a self-built image with WireGuard enabled.
> Everything below already works end-to-end there, proven against the
> **production hubs**.

## 0. Mental model

```
          internet
   ┌──────────┴───────────┐        hub JKT 163.128.54.1:51940
   │  wg-jkt / wg-mlb     │◄────── hub MLB 185.140.210.178:51940
   │  (self-managed WG)   │        (peers provisioned by the dashboard)
   └───┬───────────┬──────┘
   ISP (private)  LAN (public IPv4 /32 + IPv6 /64)
```

The **box owns its WireGuard** — the config generated by the dashboard contains
the private keys and the hub peers; there is **no wayangi agent on the box**. The
dashboard still adds the box as a peer on both hubs (like it does for a
RouterBoard). Public traffic egresses the tunnels; a private RFC1918 segment
egresses the local ISPs (NAT).

## 1. Create the site (dashboard)

1. `https://wayangi.dalang.io/admin/edge` → new site. Pick a **WayangOS** model:
   - `wos-x86-4` = **3 WAN + public LAN** (the common box), or 2/3/5-NIC variants.
   - WAN ports get DHCP by default; static ISPs use
     `WAYANGI_EDGE_WOS_WANS=eth0=<addr/prefix>@<gw>,…` on the hub.
2. The hub provisions both WireGuard peers and allocates the public `/32` +
   `/64`. Download the **WayangOS bundle** (one-time; it embeds the WG private
   keys — confidential, like a `.rsc`).

## 2. Apply on the box

```sh
scp root@box:/tmp/                                   # no — copy TO the box:
# copy the bundle (or use the dashboard's file directly), then:
wayang edgerouter apply edge-<site>.bundle.tar.gz        # or a directory; --force to overwrite
```

`apply` writes `/data/etc/router/config.toml`, `/data/etc/fw/config.toml` and
`/data/etc/router/keys/{jkt,mlb}.key` (0600) — it does **not** commit them. Review
and commit with the tools' own commit-confirm (anti-lockout):

```sh
wayang-router check && wayang-router commit --confirm 60 && wayang-router confirm
wayang-fw     check && wayang-fw     commit --confirm 60 && wayang-fw     confirm
```

Boot order is already wired: `/data` → `fw` → `network` → `sshd` → ready. The
router/firewall load their confirmed config; the monitor daemons start too (see
§5).

## 3. Verify

```sh
# tunnels up, both hubs handshaking
wg show                       # wg-jkt / wg-mlb: latest handshake, rx/tx
ip -4 route; ip -6 route      # default (v4+v6) via the tunnel group; ISP routes for the private seg
ip rule                       # policy: public srcs -> tunnel table, private srcs -> ISP table
ip -4 route show table 401    # weighted ECMP: nexthop via <hub> dev wg-… weight …
wc -c </data/var/wayang-router/history.jsonl   # monitoring is collecting
```

On a **LAN host**: it should DHCP the public `/32` (option 121 gives the default
route) and `curl https://ifconfig.me` should return the site's public address
(not NATed). From the **internet**, `ping`/`curl` the public `/32` must reach the
box/LAN host (inbound).

## 4. Failover drill

```sh
ip link set wg-jkt down            # on the box
# within a few seconds the monitor moves the group + main default to wg-mlb:
ip route show table 401 ; ip rule
# a LAN host keeps working:
#   ping -c3 1.1.1.1  (0% loss)
ip link set wg-jkt up              # it rejoins and the default returns
```

`wayang-router` logs to `/data/etc/router/router.log`; `wan.state` shows which
uplink is active.

## 5. Monitoring / forensics

`/etc/init.d/{fw,router}` start `wayang-fw` / `wayang-router monitor --daemon`
(binary + confirmed config present). They append JSON Lines to
`/data/var/<app>/history.jsonl` (rotation + retention; boot trims to the newest
20 000 records). The HUDs (`wayang-router`, `wayang-fw`) **replay history on
open**, so charts and firewall DROPS survive a close/reopen and a reboot — the
data for post-incident analysis is on `/data`. See [docs/MONITORING.md](MONITORING.md).

## 6. Troubleshooting

| Symptom | Check |
|---|---|
| No handshake | `wg show`; is the hub endpoint reachable on the WAN (UDP 51940)? Is the box's pubkey a peer on **both** hubs (dashboard site page / `edgeProvision`)? |
| Tunnel up but no internet | `ip rule` (policy route present?); `ip route show table 401` (ECMP default?); `check` warns if the kernel lacks WireGuard/multipath |
| LAN host has no address | `udhcpd` running? fw has `lan → self` `dhcp` policy? option 121 present in `/data/etc/router/udhcpd/<iface>.conf` (BusyBox wants raw hex, no `0x`)? |
| IPv6 `RA` missing | `radvd` installed (`/usr/sbin/radvd`) and `ra = true`; `diagnostics` in the router log |
| Public `/32` unreachable inbound | the `/32` must be routed to the hub upstream and the hub must route it to the box's peer (the dashboard adds this) — verify `ip route get <pub>` on the hub |
| Box froze after a kernel change | power-cycle → GRUB slot A; see the kernel interaction blocker at the top |

## 7. Anti-lockout

- Root SSH is **pubkey-only**; add keys with `wayang-addkey` (persisted in
  `/data/etc/ssh/authorized_keys`).
- `wayang-fw` keeps a management SSH rule **before** every policy; commits over
  SSH require the commit-confirm window (auto-rollback).
- The box's management access must survive interface/prefix changes — keep the
  `[management] allow_from` RFC1918 list in the generated `fw.toml`.
