# GOAL — WayangOS as a self-hosted router / firewall / Edge appliance

Single statement: **WayangOS = a tiny (RAM-boot), self-updating Linux that turns a
MiniPC into a managed router/firewall — and a *Site EdgeRouter* for the wayangi
service** (public IPv4/IPv6 to a LAN, WireGuard/VPN, BGP/OSPF/QoS, firewall) —
with the config generated by the **wayangi dashboard** and applied as pure config
on the box (self-managed WireGuard, like a RouterOS `.rsc`, no agent).

## Definition of done

- A fresh MiniPC (ThinkStation P320 Tiny class) boots WayangOS, is enrolled on
  `wayangi.dalang.io` as a **WayangOS** unit, and serves a site's public `/32` +
  `/64` to the LAN with the two production hubs as WireGuard peers.
- Router and firewall features work from the dashboard-generated config and the
  console/CLI (`wayang`, `wayang-router`, `wayang-fw`), survive reboot, and are
  observable/persistent (monitoring, logs) for forensics.
- Updates are signed A/B with anti-brick fallback and a real hardware boot test
  before every tag.

## Where M7 stands (the goal-critical blocker)

The router kernel block (WireGuard/VRF/veth/dummy/bond/gre/ipsec/QoS) is **off in
the released image** (`configs/defconfig-intel` = VLAN/bridge MVP only). 1.0.13
and 1.0.20 froze the device with the block; but a delta-debug on 2026-09-28 showed
the **full block passes** on the device (3 boots + 30-min soak) and the freeze's
signature is a **network/USB-uplink stall** (`gw=''`, clean dmesg), not a CPU
lockup → most likely **intermittent/environmental**, not a kernel-option
interaction. See [ROUTER-KERNEL-INTERACTION.md](ROUTER-KERNEL-INTERACTION.md),
[ROUTER-KERNEL-BISECT.md](ROUTER-KERNEL-BISECT.md), [INCIDENT-1.0.13.md](INCIDENT-1.0.13.md).
