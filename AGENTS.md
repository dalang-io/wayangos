# AGENTS.md — working on WayangOS

Contract for any agent changing this repo. Humans: README.md, BUILDING.md, docs/.

## What this is

Ultra-minimal Linux (kernel + BusyBox, no systemd) that runs from RAM.
Only `/data` (ext4, `LABEL=WAYANGDATA`) persists. Apps are static binaries.
Updates are signed A/B bundles (`wayang update`, docs/UPDATE-DESIGN.md).

## Rules

1. **Everything outside `/data` is rebuilt at every boot.** Anything that must
   survive goes in `/data` (config in `/data/etc/...`, deployed apps in
   `/data/bin/`). Never tell a user a `/usr/bin` copy will persist.
2. **Boot order in `rcS` matters**: mount `/data` → `/etc/init.d/fw start`
   (firewall) → network (hands interfaces to `/etc/init.d/router` when
   wayang-router has a confirmed config) → sshd → `wayang mark-ok`.
   Keep the firewall before the network.
3. **Tagging `v*` publishes a release**: `release.yml` / `installer-iso.yml`
   build the ISO and update bundle and publish the update channel on
   wayang.dalang.io (all devices see it). **Ask the owner before tagging.**
4. Scripts are bash for the build host and POSIX `sh` for anything that runs
   on the device (BusyBox ash). `shellcheck scripts/*.sh` must stay clean;
   extract heredoc'd init scripts and `shellcheck -s sh` them too.
5. Kernel configs: `configs/defconfig-qemu` is the only full config; others
   are fragments (`# WAYANG_BASE: <name>`, **one level only** —
   `build-kernel.sh` does not resolve a fragment on top of a fragment).
6. Workflow: commit straight to `master`, no PRs (owner's preference).

## Map

```
configs/            kernel configs (defconfig-intel = device/installer kernel: nftables + router options)
scripts/            build pipeline: fetch-sources, build-kernel, build-rootfs (generates /etc/init.d/*),
                    build-nft (static nft), build-bundle, ci-build ...
wayang/             Rust CLI: updater (A/B), `wayang net|wifi`, HUD
installer/          Rust installer TUI
docs/               ARCHITECTURE, UPDATE-*, NETWORK, APPS, ROUTER-TODO (router/firewall plan) ...
landing-page/       wayang.dalang.io
```

Services generated by `build-rootfs.sh`: `network`, `sshd`, `fw` (loads
wayang-fw's confirmed ruleset), `router` (applies wayang-router's confirmed
config in place of the automatic uplink setup), `rcS`, `rcK`.

## Build & test

Build on **`root@10.0.0.251`** (80 cores, cargo, qemu+KVM). Don't overwrite
`/root/wayangos-build` for experiments: use a `/tmp` BUILD_DIR with symlinks to
the sources there, and a *copy* of the kernel tree (build-kernel.sh builds in-tree).

```sh
rsync -az --delete --exclude .git --exclude dist --exclude target --exclude landing-page ./ root@10.0.0.251:/tmp/wayangos-dev/
ssh root@10.0.0.251 'cd /tmp/wayangos-dev/wayang && ~/.cargo/bin/cargo test'
./scripts/build-remote.sh      # full ISO + .wup on the box (uses /root/wayangos-build)
```

QEMU checks: direct-kernel boot with `-kernel bzImage -initrd initramfs.img`;
`vga=0x318` gives a framebuffer with the intel kernel; a `/data` disk is an
ext4 image with `-L WAYANGDATA` plus `wayang.data=LABEL=WAYANGDATA` on the
command line. The firewall lab lives in `dalang-io/wayang-fw/tests/lab/lab.py`.
